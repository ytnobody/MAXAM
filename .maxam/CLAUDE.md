### 1. 設計パターン

#### フォールバックパターン
- 設定優先 → なければデフォルト値
- 既存動作を壊さない安全な拡張
- 例: `omitempty`で後方互換維持、「空なら何もしない」

#### 段階的実装
- フェーズ分けで効果が得られる部分から実装
- nice to haveも優先度を切り分け、全部やらない勇気を持つ
- 先読み実装はスコープが明確な場合のみ（方針変更リスクあり）

#### エラーハンドリング
- バックグラウンド処理はベストエフォートで設計
- 多重防御パターン: 段階的に実行し確実性を担保
- 親切なエラーメッセージ: 「何が問題か + どうすればいいか」を1セットで

#### テスト設計
- パターンごとにグループ化（カバレッジが一目で分かる）
- 環境依存テストは `t.Skip()` で明示的にスキップ
- グローバル状態に依存しない設計（`t.TempDir()` + 環境変数オーバーライド）

#### 状態マシン設計
- 複雑なワークフローは状態遷移で表現
- 状態は明示的なenumで定義（`StateIdle`, `StateWaitingApproval`等）
- `sync.RWMutex`で並行安全性を担保
- 参考: PR #172（自動プランモード）

#### ポーリング設計
- 間隔はハードコードせず設定可能に
- デフォルト値は`Config`構造体で管理
- `context.Context`でキャンセル可能に
- 参考: PR #172（承認監視機能）

### 2. チームフロー

#### 報告フォーマット
**実装完了報告:**
1. 実装コードの要点
2. テストケース数とカバー範囲
3. テスト実行結果
4. 統合状態（例：「TUIに組み込み済み」）
5. 全機能を列挙（追加したコマンド、API等）

**調査タスク報告:**
1. 調査結果
2. 結論（できる/できない、推奨事項）
3. 次のアクション

#### GitHubアカウント制約
- オーナーPRは同一アカウントでApprove不可
- 軽微な変更はレビュアーLGTM確認後、オーナー判断でマージ

#### タスク管理
- 作業開始時にタスクボードに記載（重複防止）
- 「○○やります」と明示してから着手
- CI待ち時間を活用してスコープ確認
- **PR提出前にローカルでCI相当のチェック実施**（gofmt, go vet, テスト）

#### オーナーとチームの役割
- オーナー＝意思決定者（確認・判断をする人）
- 技術的操作（ビルド、git、テスト）はチームが担当
- 「手順を伝える」より「やっておく」が適切

#### エラー発生時のフォロー
1. PMがエラー検知したら即座に声かけ
2. 復帰確認
3. 復帰しなければ再割り当て

### 3. アンチパターン

#### 「How」と「What/Why」の混同
> 「実装できる」と「正しく設計されている」は別

**機能設計時のチェックリスト:**
- [ ] この機能は誰向けか？（オーナー / エージェント / 両方）
- [ ] この機能で何を達成したいか？（目的）
- [ ] この機能がないと何が困るか？（課題）
- [ ] 確認が必要な場合、オーナーに質問したか？

**教訓:**
> 「情報を出す側」は常に「誰がこれを知るべきか」を考える

### 4. 環境・ツール

#### Goインストール（Ubuntu）
```bash
# シンプル
sudo apt update && sudo apt install -y golang-go

# 最新版が必要な場合
wget https://go.dev/dl/go1.23.5.linux-amd64.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.23.5.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
```

#### Makefile設計
- `PLATFORMS`リストを宣言的に管理
- `dist`（単一）と`dist-all`（一括）の2段階設計
- `-ldflags="-s -w"`でバイナリサイズ削減
- バージョンは`git describe --tags --always --dirty`で自動取得

#### GitHub Actions
- イベント設計: `pull_request.closed` + `merged == true`
- 最小権限原則: 必要以上の権限を付与しない
- `GITHUB_TOKEN`を活用しセットアップコスト低減
